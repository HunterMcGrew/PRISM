Title: Architect-Context Routing Gains a Read-Triggered Mechanical Enforcement Layer
Status: accepted
Date: 2026-08-02

## Context

Architect-context routing keys on the working diff: `prism-architect`'s startup step 4 matches the current diff against `.prism/architect/manifest.json` and loads whatever docs the matched paths route to. That works when the session's diff already touches the file whose context is needed. It fails on a prompt-driven task — "add a rule about X to `code-comments.md`" carries no diff yet, or an unrelated one, so the target path's own architect doc never loads through that route. `.prism/plans/context-delivery-mechanism.md` records this as the diff-blind gap thrive PR #2247 also found and ported a prose fix for.

`Read` is a strict precondition for `Edit` on every host this project targets — the harness will not let a session edit a file it has not read. That makes a hook firing after `Read` a reliable place to land the governing doc before any edit becomes possible, landing it nearer the work than a session-start copy (the position that survives a 200k–300k-token session, per the plan's problem statement) and current because it re-reads the doc from disk on every call rather than replaying a cached one.

Three designs were on the table: (1) the prose clause alone — reliable on no host, cheap on every host; (2) a `PreToolUse` gate on `Edit` that blocks until the doc is loaded — adds friction and false positives when the doc was already read via a different route; (3) a `PostToolUse` hook on `Read` that surfaces the doc's architect context to the model, with a per-session ceiling so a wide read sweep can't repeat the same surface into every subsequent turn. Design 3 was chosen; design 1 is kept as the fallback for hosts that expose no read event. Design 3's shape narrowed during implementation — see the Decision section below for what actually ships.

Only the Claude Code host is exercised as of 2026-08-02 — Cursor and Codex adapters rest on facts that could not be run against a live host and are deferred to a follow-up PR (see the plan's host-adapter Decision).

## Decision

A `PostToolUse` hook, matched on `Read`, calls a host-agnostic resolver (`scripts/ai-skills/hooks/architect-route.ts`) that matches the read path against `.prism/architect/manifest.json` and checks a per-session state file for which matched docs have already been read. A doc is credited as read only on an observed effect — a later `Read` of that doc's own path — never on having merely been named: naming a doc is not delivering it, so an unread doc keeps being named on every subsequent read of a path that matches its route. For every still-unread matched doc, the resolver returns a single nag payload naming it by path, capped at a per-emission byte ceiling (`MAX_EMISSION_BYTES`) so a future manifest fan-out cannot silently spill past the channel's cap — with one exception: the nag never emits zero docs, so a single doc's own formatted entry is still emitted even if it alone exceeds the ceiling. No manifest doc path in this repo is anywhere close to that length today, so the exception has no live trigger. No doc body is ever injected. The Claude Code adapter (`scripts/ai-skills/hooks/claude-post-read.ts`) is registered in `.claude/settings.json` and is the only adapter this decision ships; Cursor and Codex adapters are a follow-up PR gated on host access, sharing the same resolver.

The prose fallback in `.prism/rules/context-reuse.md` is not made redundant by the hook and is kept deliberately: it is what runs on every host, including ones with no read-hook adapter yet, and it degrades gracefully to a no-op cost (a few sentences of always-on rule text) rather than to silence.

The mechanism is repo-local as of this decision. `package.json`'s `files` array ships `dist/`, `.prism/{rules,architect,spec,references,templates}`, `templates/install/`, and `.ai-skills/skills/` — not `scripts/` — so neither `architect-route.ts` nor `claude-post-read.ts` reaches a consumer install today, and no consumer's `.claude/settings.json` is touched. `templates/install/.claude/settings.json` stays `{}` on purpose: seeding a registration there would point every consumer at a script path absent from the published package, and because the hook fails open, a consumer would never discover the resulting dead hook. The registration becomes live only once `scripts/ai-skills/hooks/` ships in `files` and that seed is updated to match — tracked as follow-up work alongside the Cursor and Codex adapters.

The hook carries a `PRISM_HOOK_DISABLE=1` kill switch, checked before stdin is even parsed, so an experiment or a debugging session can register the hook and still run with it inert — varying exactly one thing (behavior) without touching registration (`.claude/settings.json`) or the manifest.

## Consequences

- **Positive:** On Claude Code, a `Read` of a path matching a `manifest.json` route reliably names every unread matched doc by path — a nag, not a body — before any `Edit` of that path is possible. This narrows what the hook guarantees: it does not put a doc's content in front of the agent automatically, only its name, and a doc credits as delivered only once the agent's own subsequent `Read` reaches that doc's path. What the hook removes is the failure points a prose-only reminder is exposed to — remembering to check, finding the manifest, reading it in full, matching correctly, re-matching when scope changes — leaving one: the agent choosing to read a doc it has now been told, programmatically and on every turn that still needs it, that it hasn't read. Whether that remaining step changes what the agent produces is the open question the Neutral bullet below records. It does not displace the prose fallback in `.prism/rules/context-reuse.md`, which is `load: always` and still reaches every session on every host by design (see the Decision section).
- **Positive:** Route resolution is programmatic, so the agent never reads `manifest.json` at all. `resolveArchitectNag` parses the whole manifest and runs every pattern against the read path on each call. Three failure modes the prose fallback permits are therefore **structurally impossible** for the hook: matching against a *partially read* manifest (a real observed failure — a session read a 124-line manifest via `head -60`, saw 48% of it, and never re-read; a route sitting one line past the cutoff was consequently invisible); matching **once** and never re-matching when new paths enter scope later in the session; and **skipping** the match. Each of these is a step a human-or-agent reader can omit and a program cannot. What this bullet does not claim: that the hook always fires (it is deliberately fail-open), that every path matches a route, or that a named or delivered doc is attended to once it arrives.
- **Positive:** The payload is a nag, not a body — every matched-but-unread doc is named by its path only, and no doc body is ever injected. A per-emission ceiling (`MAX_EMISSION_BYTES` in `architect-route.ts`) bounds the joined nag text, with one named exception: the nag never emits zero docs, so a single over-length doc path is still emitted alone even past the ceiling — no manifest doc path in this repo is anywhere close to that length, so the exception has no live trigger today. Today's nag sits well under the ceiling on this repo's own manifest, but nothing about path-matching bounds how many docs a future route could fan out to, and the ceiling is insurance against that growth rather than what keeps today's nag safe.

  **This replaces an earlier design that inlined whole doc bodies up to a 4000-byte-per-doc cap, and that design's defect is worth recording rather than erasing.** With no ceiling on the sum of per-doc caps, one measured `Read` produced a 92,366-byte joined payload (~23k tokens). Framing that as 23k tokens of cost overstated it: Claude Code's `additionalContext` channel caps at 10,000 characters (verified against Claude Code's hooks reference) and replaces any overflow with a file preview the model never opens, so at most roughly 10,000 of those 92,366 bytes could have reached the model — the phantom share was roughly 89%, not the full amount. The real defect was silent non-delivery, not token spend: the docs were read from disk and marked delivered at that moment, but most of what left the hook never arrived, and the delivery-tracking bug this ADR's Decision section now describes (credit on an observed read, never on emission) is what closes it. The original finding and the per-doc cap were both sound engineering; only the stated reason for the cost was wrong.
- **Negative (deferred, not current):** today the mechanism is repo-local — see the Decision section above — so no consumer install merges into anything yet. Once `scripts/ai-skills/hooks/` ships in `files` and the registration is seeded, a third consumer config surface (`.claude/settings.json`, alongside `.cursor/` and `.codex/` equivalents once those adapters ship) will have to be merged into on every install, not overwritten — a hazard the registration step (task 3) is written to avoid but that every future editor of that file will have to keep respecting.
- **Negative:** A hook that errors or times out fails silently — no doc is injected and no error surfaces in the transcript — which is a worse failure mode than the file-based always-on delivery this decision deliberately keeps separate (see the plan's "Hooks earn their place only where no file-based mechanism exists" Decision). The adapter is written to fail open (catch, log to stderr, exit 0) specifically so a hook fault degrades to "no injection," not to a blocked or broken read.
- **Neutral (delivery established, behavior still open):** These are two questions and only one is answered.

  **Delivery — answered.** The prose fallback does not reliably load the docs it names. Observed in an unmodified real session with no hook, under an explicit instruction to match every file against the manifest and load every matched doc: the manifest was read once and truncated, matching ran once for a single file, one prompt loaded 1 of 4 matched docs, and a follow-up prompt introducing files in a different workspace loaded 0 of ~11 with no re-match performed. No ADRs were read at any point. The should-have-loaded counts are undercounts — the audit behind them does not expand brace globs — so the real miss rate is worse, which biases *against* the mechanism rather than for it.

  **Behavior — open.** Whether injecting those missed docs would have changed the agent's output is not established, in either direction. A delivery gap is necessary for the hook to help, not sufficient: a doc that would not have changed the output is a doc whose absence cost nothing. **Nothing here should be read as evidence that the hook improves outcomes.**

  An earlier synthetic A/B harness (built, smoke-run once, then deleted; the design record and its six smoke rows are in `.prism/plans/context-delivery-mechanism.md`, tasks 9 and 17) could not have settled either question: its runs were single-shot against a fresh worktree, so the graded read was the agent's first action and the `load: always` prose reached both arms at full recency. Its control scored 100% where the field control scores roughly a quarter. **This decision is not reverted on a null from that harness**, and no such harness exists to produce one. Until the behavior question is settled, the mechanism is kept on the delivery finding plus a cost judgment — bounded bytes per matched `Read`, one process per `Read`, fail-open — and not on demonstrated outcome improvement.
