# Hook Runtime

The hook runtime PRISM installs into a consumer's agent hosts: how `prism update` delivers it, the state it keeps, and the gates it enforces. Where the rest of an install lives and who owns it is [`install-layout.md`](./install-layout.md). How `prism adopt` and `prism update` run is [`consumer-sync-flow.md`](./consumer-sync-flow.md).

---

## Hook runtime

**Delivery path.** `refreshHookRuntime` copies the runtime files listed in `HOOK_RUNTIME_FILES` (the `.mjs` modules, not their `.d.mts` sidecars) into the consumer's `.claude/hooks/`. `hook.mjs` and `git-gates.mjs` are the two entry points, and both get the executable bit. The runtime is delivered when the consumer's `hosts` (`.ai-skills/config.json`) includes `claude` or `codex`. Absent means every host, so an existing install keeps receiving it with no migration. Each host's registration is merged only for that host: `.claude/settings.json` for `claude`, and `.codex/hooks.json` for `codex` via `mergeHookCodexRegistration`. Both templates register the same three events: `PreToolUse`, `PostToolUse`, and `PostCompact`. The merge composes within each event's array. `mergeHookEventEntries` drops only PRISM's own prior entries and appends the current ones, so a consumer's own entries on the same event survive every update. Dropping one host removes only its registration on the next update. The runtime files are removed only when both are gone. The `.gitignore` lines below stay after a host is dropped, because no update path removes them. Cursor is the only host without a delivery path. The resolver reads Cursor's payload shape, but no install path writes a Cursor hook file, and `HARNESSES.cursor.emitDeny` returns `null`. Wiring it up is follow-up work rather than a setting a consumer can flip.

**The asymmetry is a decision, not an oversight.** Enforcement reaches Claude Code and Codex. On Codex the delivery is verified, but the deny envelope is documentation-verified, not live-probed (`HARNESSES.codex.emitDeny` in `scripts/ai-skills/hooks/harnesses.mjs`). No measured session has yet shown a Codex deny reason reaching the model. Cursor keeps the always-on prose fallback. [ADR-0077](../../spec/adrs/_toolkit/0077-hook-enforcement-reaches-claude-code-and-codex.md) records the call and the alternatives rejected to reach it: amending the earlier Claude-only ADR in place, holding the Codex deny until a live probe, a registration in the per-user `codex-config.toml`, and a second runtime copy. It supersedes [ADR-0074](../../spec/adrs/_toolkit/0074-hook-enforcement-is-claude-only-with-a-prose-fallback.md), whose rejections of a git `pre-commit` floor and of levelling down by removing the gate still stand.

**State file.** Read-tracking is per scope, in `.prism/architect-route-state.<scope-id>.json`. Each host's `scopeId` in `harnesses.mjs` decides the scope id. Claude Code uses the session id and appends the agent id for a subagent, so a Claude subagent has its own scope. Codex uses `session_id` with no agent suffix. Cursor uses `conversation_id`. A `.tmp` sibling sits beside it during the atomic write. It is a cache and not a record: an unreadable or unrecognized file reads as absent, which costs one repeated announcement rather than bricking the hook. `git-gates.mjs` keeps its own family beside it, `.prism/git-gates-state.<scope>.json`, keyed by the same scope id and the HEAD sha. `refreshHookRuntime` appends a line for each state-file glob and its `.tmp` sibling to the consumer's `.gitignore`, on adopt and on every update that delivers the runtime. The write is append-only, skipping lines already present, so the files never reach a commit. Those lines are the whole of what PRISM writes there. Nothing else in a consumer's `.gitignore` is touched.

**Switches.** `PRISM_HOOK_DISABLE=1` makes the runtime inert before it parses stdin, so a session can keep the registration and still run without the hook — one variable changes behavior without touching a registration file or the manifest. `PRISM_HOOK_DENY_DISABLE=1` is the narrower switch: it turns off both the write gate and the git gates while leaving announcements on.

## Write gate

A call that touches a path matching any manifest route is denied until the route's docs have been read ([ADR-0072](../../spec/adrs/_toolkit/0072-write-gate-on-routed-paths.md)). One rule covers a `Write`, an `Edit`, and a `Bash` command alike, so a delete or a move gates the same way a write does and no list of delete verbs has to be kept current. Claude Code registers it as `PreToolUse` matched `Write|Edit|Bash`. Codex registers it as `^(Bash|apply_patch|Edit|Write)$`. Cursor gets no registration, the same delivery gap § Hook runtime states.

**What triggers a deny.** All five of: no kill switch set, a scope id on the payload, a tool whose kind the harness's table explicitly lists as `write` or `shell`, a manifest route matching the path, and at least one of that route's docs neither read this scope nor missing from disk. An unrouted path is never denied on any verb — a route existing is the opt-in, which is what keeps a fresh install from blocking a consumer's first edit to their own code.

**What clears it.** Reading each doc the message names, in full, through a channel the credit channel observes: a `Read` with no `offset` or `limit`, or a flagless `cat`. The message names the literal `cat` command per doc, because credit turns on the shape of the call and a remedy the model has to infer is one it cannot reliably perform. A `head`, a ranged `Read`, or a `Grep` naming the doc credits nothing.

**A shell command gates on the same rule, minus what it can prove it only reads.** No parser short of a real shell can say what an arbitrary `Bash` command does to a path it names, so the arm never tries. Every path-shaped token in the command is a candidate. A token is dropped only when the whole command is provably a set of commands that write no working-tree file, carrying only flags that command cannot write or execute through, and the token is one of their operands. Most of that set is read-only commands such as `cat`, `grep`, `ls`, and a `git` whose subcommand only reads. The rest is `git` subcommands that write only inside `.git/`, such as `commit`, `add`, and `push` (`GIT_TREE_SAFE_SUBCOMMANDS` in `hook.mjs`). So `git add` on a routed doc is not gated. A surviving token that matches a route is judged exactly as a write is. Both arms rewrite `\` to `/` first, wherever the next character is path-shaped, so a Windows-spelled path is one token on every platform — the rewrite keys on that following character rather than on `path.sep`, which is what keeps a single code path both CI legs execute. A read the rewrite changed announces its docs but does not clear them, because credit turns on the shape of the call rather than on what the shell delivered. The deny message already prints the forward-slash spelling, and that spelling clears everywhere.

The proof is an exemption, not a verdict: a flagless `cat` is exempt because denying it would deny the remedy the deny message asks for. The arm over-denies on purpose — a read it cannot prove costs one doc read, which is more forced reading than the respelling a reroute used to ask for, and it clears for good instead of re-firing.

**Three gaps survive.** A write whose target path never appears in the command text — built from a variable, or reached by a `cd` — is invisible to any scan over the command. The exemption lists are the second. Command membership has an executable check: `hook-gate.test.ts` runs every listed shell command against a scratch file and asserts the file is unmodified. Flag membership has no such check and stays a human judgment, so a flag wrongly admitted is a silent write rather than an extra read. `sort -o`, `uniq <in> <out>`, `git diff --output`, and `sed`'s `w` script command each proved that direction once. The third is a deadlock rather than a leak — an architect doc whose own path carries a character outside the read-safe class cannot be `cat`-ed provably, and `.prism/architect/**` is routed, so the remedy gates itself. See [ADR-0072](../../spec/adrs/_toolkit/0072-write-gate-on-routed-paths.md) § Consequences.

**The gate is friction, not a wall.** Deleting the registration, deleting `.claude/hooks/hook.mjs`, or setting `PRISM_HOOK_DENY_DISABLE=1` each disables it; all three are trivial and none is prevented. The hook's consumer-side files, `.claude/hooks/`, `.claude/settings.json`, and `.codex/hooks.json`, are deliberately unrouted, because in a consumer repo those files belong to the consumer. The compensating control is visibility. `prism doctor` reports a hook missing one half, either a runtime with no registration or a registration pointing at a missing file. Removing both halves looks the same as never having received it, so doctor stays quiet. It reports per host whether the runtime is installed and registered. It warns when a dropped host's registration is still on disk, or when the runtime remains after both `claude` and `codex` left `hosts`.

### Git gates

Two author-side gates ride the same runtime as a second entry point, `git-gates.mjs`, registered on its own `Bash` matcher group so it never spawns on a `Write` or `Edit`. Both watch the shell tool's `PreToolUse` event and recognize a `git commit` or `git push` segment in the command text — no harness exposes a pre-commit event of its own. The commit gate holds the first `git commit` on each HEAD sha once per session, naming `.prism/references/cleanup-pass.md` as the remedy; the retry of the same command goes through, because the state is saved before the deny. The push gate runs `commands.lint` and then `commands.format` from `.ai-skills/config.json` and denies the push with the output tail on a non-zero exit.

Both are off until the consumer sets them: a `hooks` block in `.ai-skills/config.json` carrying `commitCleanupPass`, `pushVerification`, and an optional `pushVerificationTimeoutMs` (120 s by default). The block is read by the runtime, not a persona, which is why it is its own top-level key rather than a `features.*` entry. A config with no block, a config that is not valid JSON, and either kill switch above all leave the gates inert. The config that governs a `git` call is found by walking up from the directory the call runs in — the session's working directory with any `-C` applied — and no further than that repo's own toplevel, so a separate nested repo is governed by its own config or by none, and its push never runs the enclosing repo's `commands.*`.

The push gate fails open on anything but a real non-zero exit: a command that exceeds its budget or cannot start allows the push and says so, on stderr and — where the host renders one — in an allow envelope carrying the same line. A deny on a timeout would ask for a remedy the retry cannot perform, and a silent allow would make a broken lint command indistinguishable from a passing one. The decision record, with the alternatives rejected on the way to it, is [ADR-0076](../../spec/adrs/_toolkit/0076-commit-and-push-gates-are-harness-hooks.md).

### Hook-runtime ownership and recovery

**The runtime is zero-dependency `.mjs` because the consumer may have no `node_modules` to point at.** Every module under `scripts/ai-skills/hooks/` imports only `node:` builtins and its own siblings, and the registration invokes plain `node` — an `npx`-installed consumer has no package tree, so a `tsx` or `node_modules` invocation would be a permanent no-op there. Types ride `.d.mts` sidecars beside each module, which is what lets `tsc` resolve a `.mjs` specifier under the root `moduleResolution` with no tsconfig change. `compileMatcher` has exactly one implementation, `hooks/lib/match.mjs`; `verify-manifest-coverage.ts` and `ownership.ts` both import it from there, so a matcher change cannot land in one copy and miss the other.

**Ownership of a delivered file is content-keyed, not path-keyed.** `.claude/hooks/` sits outside the sync manifest's content root, so there is no recorded hash to tell PRISM's older copy from a consumer's hand-edit the way `applyIncomingFile` can. The `HOOK_RUNTIME_MARKER` line the shipped files carry is the only signal available. A marked file is PRISM's content at whatever version wrote it. A marked file at a delivered path is replaced without a backup by `deliverHookRuntimeFile`. A marked file anywhere else under `.claude/hooks/` is backed up and removed by `pruneStaleHookRuntimeFiles`. An unmarked file at a delivered path is the consumer's, so it is preserved as `.bak` before PRISM's copy replaces it. An unmarked file at any other path is never touched.

**Ownership of a registration is pattern-keyed, and the two rules answer different questions.** `mergeHookEventEntries` claims an entry only when its command matches the host's pattern end to end: `PRISM_HOOK_COMMAND_PATTERN` for `.claude/settings.json` or `PRISM_CODEX_HOOK_COMMAND_PATTERN` for `.codex/hooks.json`. A consumer who wrapped or edited PRISM's command no longer matches it, so their entry is neither refreshed on delivery nor dropped when its host leaves `hosts` — and after a removal it points at a runtime file that is gone. Loosening the anchor to catch that case would let removal delete a consumer's own wrapper, so the compensating control is reporting rather than claiming: doctor's dead-registration check runs on every host mix, not only when `hosts` includes a delivering host. Scoping it to the delivery branch reintroduces exactly the silent case the anchor accepts.

The two paths carry different risk and the code treats them differently on purpose: delivery replaces a marked file without a backup because it runs on every update, while prune backs the file up first because it fires rarely and a marked file at an unrecognized path is plausibly a consumer's own adaptation that carried the marker along.

**Backups are skipped by name, never by content.** `backupConsumerFile` copies byte for byte, so a `.bak` always inherits its source's marker — content is structurally incapable of separating a backup from the file it copied. `pruneStaleHookRuntimeFiles` therefore excludes backup basenames (`BACKUP_BASENAME_PATTERN`, defined beside `HOOK_RUNTIME_MARKER`) before the marker check. Without that filter prune re-selects the backup it just wrote: measured over four update runs as `.bak` → `.bak.bak` → `.bak.bak.bak` → `.bak.bak.bak.bak`, with run N's recovery copy already gone by run N+1.

**A recovery `.bak` is the consumer's to delete, never PRISM's to reclaim.** The name filter's cost is that a genuinely stale marked `.bak` is left in place rather than swept. That is the intended trade — the backup may be the only surviving copy of consumer-authored bytes, and a sweep that reclaims it defeats the guarantee it exists to provide.
