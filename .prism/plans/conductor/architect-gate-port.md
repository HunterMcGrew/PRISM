## Design decisions — settled at the 2026-08-18 grilling gate (Hunter, in-session)

The operator decision record. winston transcribes these into `opus5-port.md` `## Decisions` at re-plan; this section is the authority if they diverge.

- **Q1 — Day-one guards.** The consumer stub ships instruction-layer routes (plans, rules, architect docs, ADRs, skills), each pointing at a shipped writing guide. Creating or editing any instruction file denies until its guide is read — from file zero. App code is unrouted until the consumer authors docs for it; no route → no fire, by design.
- **Q2 — Route integrity.** No frontmatter. Guides make route-add part of authoring and route-verify part of editing. `prism doctor` gains two checks: orphan docs (doc on disk, no route) and dead routes (route naming an absent doc). The hook nags once at authoring time when a new doc lands unrouted. Closure: docs-on-disk vs manifest set comparison, consumer-runnable via the shipped CLI.
- **Q3 — Deny everywhere a route exists.** No code-route/authoring-route split. Hunter's own testing: forced reading works, nags read as boilerplate. Thrive's nag-forever-on-code-routes design is explicitly not ported.
- **Q4 — Manifest stays flat.** Deny is universal behavior, not per-route data — no `deny` flag, no sections, no schema change, no migration, no major bump. Catch-alls (`**`, bare `*`, any pattern matching the empty string) are rejected at validation; the stub's `"**"` route dies.
- **Q7 — Announce once, enforce at write.** Read of a routed path names each unread doc exactly once per session, never repeated (kills the ~6-nag habituation Hunter observed). Enforcement is the write-time deny alone. No fallback nag arm: Claude, Cursor, and Codex all support `PreToolUse` deny (Codex verified against its hooks docs this session — thrive's "Codex has no PreToolUse" was a registration choice, not a platform limit). Compaction reset moves to `PostCompact`, portable via `--tool=`.
- **Credit channel (ship-gate, not a choice).** Credit must widen to Bash read commands (`cat`/`head`/`sed -n`) and `Grep` in the same PR as the deny, or the remedy is unperformable under Hunter's own output style. sasha's blocker stands. `Read(limit=1)` full-credit is a known accepted gap unless winston prices a fix cheaply.
- **Q6 — File grain keys on load mechanism.** Always-on rules may group (`code-standards-js` stays one file). Routed docs split until the "and" test passes, with specific path patterns. Split-on-touch — except the writing guides, the stub's route targets, and `skills-ecosystem.md`, which split now (they are the deny's remedy docs; a forced read must be cheap).
- **Q5 — Ship surface: four things plus dependency closure.** Skills (personas + skill-forge), rules, writing guides, runtime (hooks, stub, doctor). Everything link-reachable from those ships (ADR-0046 and SPEC.md earn their place this way); everything else — PRISM's plans, self-dev ADRs, self-dev references — stays home. Closure enforced in `prism:check`. Atlas's onboarding deps (`references/onboarding/`, `closing-messages.md`) ride the closure.
- **SPEC.md ships.** It is the tier-system meta-doc (rule vs architect doc vs ADR placement), cited by shipped `code-standards.md` and routed by the stub's first key — in-closure. Needs a genericizing pass (drops "PRISM Spec" title, hardcoded `.claude/` paths) for LLM-agnosticism.
- **Q8 — Decision guards: dead.** Hunter has never had a plan Decision deleted or overridden; fails the deletion test. No `ask` mechanism, no plan parser. If ever needed: a decision worth protecting gets a one-thing doc and a route — the existing mechanism covers it.
- **Q9 — Sequencing.** PR 0 (delivery fixes) ships first, alone. Then winston's re-plan stack.
- **LLM-agnostic.** One zero-dependency `.mjs` runtime, per-harness rows in the `HARNESSES` table only, doctor/lint checks harness-free. All three harnesses get the deny.
- **Identity note.** PRISM is becoming Hunter's personal tool (synced into thrive). Consumers extend via their own repo (skill-forge, own docs/rules); they don't edit PRISM's shipped internals.

## Subagent context: settled, plus a new gap it exposes — 2026-08-19 (Hunter, in-session)

**Decision: each agent reads for itself. Confirmed, not inherited.** ADR-0072 was drafted to name credit-leak-via-subagent as a known consequence. PR #468 closed that leak, so the honest consequence is the opposite one and it must be recorded as **chosen**: a subagent doing routed work pays the read cost fresh even when its parent already read the same doc. Hunter's reason — a dispatch may be one simple agent or many agents in an orchestrated run, and there is no way to know from inside the hook which shape you are in, so the safe default is that context does not travel and every agent earns its own.

**The gap this exposes, and it is a live oversight, not a 2D task.** If every agent must read for itself, then **an orchestrator dispatching subagents has to inject only the context relevant to that subagent's lane.** Today nothing enforces that — a dispatch brief is hand-written prose, so relevance is the dispatcher's judgment with no mechanism behind it. Two failure directions, both real: over-injection buries the lane's actual constraints in unrelated context, and under-injection sends an agent into routed work whose docs it will now be denied for, having been told nothing. This run produced instances of both — Sol over-injected by overriding a persona's own operating instructions (see § Dispatch-brief discipline), and under-injected by naming three findings to the reviewer while never routing them to the implementer (see iris's `sol — split reviewer-suppression from implementer work order` action item).

**Not scoped here.** It needs its own pass — the question is whether relevance can be computed (from the lane's file set against the manifest, the same match the hook already performs) or whether it stays a judgment with a checklist. Recorded so the 2D close does not absorb it silently.
